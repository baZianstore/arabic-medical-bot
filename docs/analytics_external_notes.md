# ملاحظات خارجية لتصميم التحليلات

## Supabase

أوضح سجل تغييرات Supabase بتاريخ 2026-04-28 أن الجداول الجديدة في `public` لن تُعرض تلقائيًا لواجهات Data وGraphQL تدريجيًا، مع تطبيق شامل مخطط في 2026-10-30. لذلك يجب ألا يعتمد التنفيذ على منح تلقائية، بل يحدد المنح صراحة. المصدر: https://supabase.com/changelog.md

يوضح دليل تأمين Data API أن **Postgres grants** تحدد من يمكنه بلوغ الكائن، بينما تحدد **RLS** الصفوف المتاحة بعد ذلك. ينصح الدليل باستخدام الطبقتين، وإلغاء الصلاحيات الافتراضية، ومنح أقل قدر لازم. كما يذكر أن الدوال لا تخضع لـRLS، ولذلك يجب تقييد `EXECUTE` صراحة. المصدر: https://supabase.com/docs/guides/api/securing-your-api.md

## قرار التطبيق

ستبقى جداول التحليلات والربط غير متاحة لدوري `anon` و`authenticated`. سيُمنح `service_role` فقط الصلاحيات اللازمة. ستعمل دالة الزيادة الذرية بصلاحية المستدعي `SECURITY INVOKER`، مع سحب `EXECUTE` من `PUBLIC` ومن أدوار العميل ومنحه إلى `service_role` وحده.

## الجدولة

التقرير حساب حتمي أسبوعي لا يحتاج نموذج ذكاء اصطناعي. سيُنشأ من خدمة Render نفسها عند تنفيذ مهمة النشر اليومية يوم الأحد، مع حاجز idempotency في Supabase. هذا يعيد استخدام آلية إيقاظ Render الحالية ويمنع تكلفة تشغيل وكيل ذكاء اصطناعي دوري.
