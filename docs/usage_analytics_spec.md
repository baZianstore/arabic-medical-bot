# مواصفة تقرير تفاعل البوت الأسبوعي

> `SECURITY-GATE: healthcare-app-security-guardrails loaded — phase=design — status=ENFORCED`

## الهدف

إضافة لوحة إحصاءات للمشرف ورسالة Telegram أسبوعية تلخص تفاعل الجمهور مع `@Intmed_edu_bot`. يبدأ القياس من لحظة نشر الميزة؛ لا تُستعاد أحداث سابقة غير مسجلة.

## الافتراضات المعتمدة

يُرسل التقرير صباح كل أحد بعد تشغيل مهمة النشر اليومية وفق `Asia/Jerusalem`. يستطيع المشرف تغيير مستلم الرسالة بإعادة الربط من لوحة الإدارة. تُعرض آخر 7 أيام وآخر 30 يومًا في اللوحة، بينما تغطي الرسالة الأسبوعية الأيام السبعة المكتملة السابقة وتقارنها بالفترة السابقة عند توفر البيانات.

## تقليل البيانات

لا يُخزن أي معرف مستخدم مع أحداث التفاعل. لا تُخزن أسماء المستخدمين أو نصوص الرسائل أو عبارات البحث أو إجابات الأفراد أو الوقت الدقيق للحدث. السجل الوحيد هو عداد يومي مجمع بالمفاتيح: `metric_date`, `event_type`, و`topic_id` الاختياري. يُخزن معرف دردشة إداري واحد في جدول منفصل للتوصيل فقط، ولا يُربط بجدول العدادات.

## المؤشرات

| المؤشر | طريقة الحساب |
|---|---|
| إجمالي التفاعلات | مجموع الأحداث المسموح بها خلال الفترة |
| مشاهدات الموضوعات | `topic_view` |
| تفاصيل الموضوع | `topic_detail_view` |
| فتح المراجع | `sources_view` |
| بدء الاختبارات الإنجليزية | `quiz_en_started` |
| إجابات الاختبارات الإنجليزية | `quiz_en_answered` |
| دقة الاختبار الإنجليزي | `quiz_en_correct / quiz_en_answered` |
| البحث الناجح وغير الناجح | `search_success` و`search_empty` |
| أكثر الموضوعات مشاهدة | تجميع `topic_view` حسب `topic_id` |
| نمو التفاعل الأسبوعي | مقارنة المجموع الحالي بالأيام السبعة السابقة |

لا يُعرض «المستخدمون الفريدون» لأنه يتطلب معرفًا قابلًا للربط، ولا يجوز استنتاجه من عدادات مجهولة.

## ربط مستلم Telegram

ينشئ المشرف من صفحة التقرير رمزًا عشوائيًا لمرة واحدة صالحًا عشر دقائق. يُخزن SHA-256 فقط، ثم يرسل المشرف الأمر `/link_report <token>` إلى البوت في محادثة خاصة. عند نجاح المطابقة يُحذف الرمز وتُحفظ `telegram_chat_id` للتوصيل الإداري فقط. لا تُقبل المجموعات ولا رمز منتهي أو معاد الاستخدام.

## مصفوفة الصلاحيات

| الدور | المورد | الفعل | النطاق | السماح | المنع الصريح | موضع الإنفاذ |
|---|---|---|---|---|---|---|
| مستخدم Telegram | عدادات مجهولة | زيادة عداد | حدث حالي فقط | event type من allowlist وtopic id معروف | لا قراءة، لا معرف مستخدم، لا نص بحث | `bot.py` و`database.py` |
| مشرف الويب | التقرير | قراءة | عالمي مجمع | جلسة `admin` وGET | مجهول الهوية | `login_required` في Flask |
| مشرف الويب | رمز الربط | إنشاء/إبطال | singleton | جلسة `admin` وCSRF | مجهول أو GET أو رمز خام في قاعدة البيانات | Flask وSHA-256 |
| مستلم Telegram | ربط التقرير | تعيين chat id | محادثة خاصة | رمز صحيح وغير منتهٍ | مجموعة، رمز خاطئ، منتهٍ أو مستخدم | معالج `/link_report` |
| حساب الخدمة | جداول التحليلات | قراءة/كتابة | عالمي | مفتاح خادمي في Render | `anon`, `authenticated`, `PUBLIC` | grants وRLS |
| المجدول | إرسال التقرير | تنفيذ | أسبوع واحد | سر المجدول أو APScheduler + claim فريد | تكرار الأسبوع أو مستلم غير مربوط | Flask/JobQueue وSupabase |

## التخزين والاحتفاظ

تُحفظ العدادات اليومية 400 يوم لتوفير مقارنة سنوية مستقبلية، ثم تُحذف أثناء مهمة التقرير. يحتفظ جدول سجل التقارير بحالة آخر 60 أسبوعًا لأغراض منع التكرار والتدقيق التشغيلي. لا تتضمن هذه الجداول بيانات سريرية أو أحداثًا فردية.

## معايير القبول

1. تعرض `/analytics` للمشرف فقط آخر 7 و30 يومًا واتجاهًا يوميًا وأفضل الموضوعات.
2. تزيد الأحداث المسموحة عدادًا مجمعًا ولا تتغير تجربة البوت عند تعطل القياس.
3. لا تقبل طبقة البيانات event type أو topic id غير معروف.
4. ينجح الربط فقط برمز صحيح، في محادثة خاصة، ولمرة واحدة.
5. يُرسل تقرير واحد كحد أقصى لكل أسبوع، ويعاد السماح بالمحاولة عند فشل Telegram.
6. لا تظهر معرفات مستخدمين أو نصوص رسائل أو أسرار في التقرير أو السجلات.
7. تمر اختبارات الوحدة والتكامل والأمان، وتُطبق جداول الإنتاج، ثم يجتاز تقرير اختباري يدوي.
